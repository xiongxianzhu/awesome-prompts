# 全栈应用项目生成器

## 📋 基本信息

- **分类**: development/project-generation
- **适用模型**: GPT-4, Claude 3, Gemini Pro
- **难度**: 中级
- **标签**: full-stack, project-generation, architecture, coding, development
- **贡献者**: awesome-prompts

## 🎯 使用场景

适合快速生成一个完整的全栈应用项目，包括前端、后端、数据库等完整技术栈的项目结构和基础代码。

## 💡 提示词内容

```
我需要你帮我生成一个完整的全栈应用项目。请根据以下要求，创建一个生产就绪的项目结构：

## 项目要求
**项目名称**: [你的项目名称]
**项目描述**: [简要描述项目功能和目标]
**主要功能**: [列出3-5个核心功能]
**用户群体**: [目标用户群体]

## 技术栈偏好
**前端框架**: [React/Vue.js/Angular/Next.js等]
**后端框架**: [Node.js/Python/FastAPI/Java/Spring Boot等]
**数据库**: [PostgreSQL/MongoDB/MySQL/SQLite等]
**认证方式**: [JWT/OAuth2/Session等]
**部署环境**: [Docker/AWS/Heroku/Vercel等]
**其他技术**: [Redis/WebSocket/GraphQL等]

## 设计要求
- 使用现代化的架构模式（如微服务、分层架构等）
- 包含完整的用户认证和授权系统
- 实现RESTful API或GraphQL接口
- 包含前端UI/UX设计
- 考虑性能优化和安全最佳实践
- 包含单元测试和集成测试
- 添加日志记录和错误处理
- 包含API文档（Swagger/OpenAPI）

## 生成格式
请按以下结构生成：

### 1. 项目概览
- 项目架构图
- 技术选型说明
- 开发环境要求

### 2. 目录结构
完整的项目文件夹结构，包含所有必要的文件和目录

### 3. 核心文件内容
- package.json / requirements.txt
- 主要配置文件
- 入口文件代码
- 数据库模型
- API路由定义
- 前端组件结构

### 4. 开发指南
- 环境搭建步骤
- 开发工作流
- 部署说明
- 测试策略

### 5. 扩展建议
- 可选的增强功能
- 性能优化建议
- 安全注意事项

请确保生成的代码是生产就绪的，遵循最佳实践，并包含详细的注释和说明。
```

## 📝 使用示例

### 示例1：电商应用

**输入**：
```
项目名称: MiniShop
项目描述: 一个小型的在线购物平台
主要功能: 用户注册登录、商品浏览、购物车、订单管理、支付集成
用户群体: 小型企业和个人卖家

前端框架: React
后端框架: Node.js + Express
数据库: MongoDB
认证方式: JWT
部署环境: Docker
其他技术: Redis(缓存), Stripe(支付)
```

**输出**：
完整的项目结构包括：
- 前端React应用（用户界面、商品展示、购物车等）
- 后端Node.js API（用户管理、商品管理、订单处理等）
- MongoDB数据库模型
- JWT认证系统
- Redis缓存层
- Stripe支付集成
- Docker配置
- 开发和部署文档

### 示例2：社交媒体应用

**输入**：
```
项目名称: SocialHub
项目描述: 轻量级社交媒体平台
主要功能: 用户资料、发布动态、评论点赞、实时聊天
用户群体: 年轻用户群体

前端框架: Vue.js
后端框架: Python FastAPI
数据库: PostgreSQL
认证方式: OAuth2
部署环境: AWS
其他技术: WebSocket(实时消息)
```

## ⚙️ 参数说明

- **项目名称**: 影响所有配置文件和命名
- **技术栈**: 决定项目结构和依赖管理
- **功能需求**: 影响数据库模型和API设计
- **部署环境**: 影响配置文件和Docker设置

## 🔧 技巧与建议

1. **明确需求**: 在使用前先明确项目的核心功能和技术需求
2. **分步实施**: 生成项目后按模块逐步实现功能
3. **自定义调整**: 根据实际需要调整生成的代码结构
4. **版本控制**: 立即初始化Git仓库开始版本管理
5. **环境配置**: 仔细配置开发环境，确保所有依赖正确安装
